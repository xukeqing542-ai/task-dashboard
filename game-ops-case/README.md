# 海外游戏运营个人案例：活动、玩家反馈与贡献利润

**性质：**可运行的个人演练。`output/players.csv` 和 `feedback.csv` 均由脚本生成，未使用三七互娱玩家、产品、广告后台或公司数据；活动未实际投放。

## 业务问题与方案

演练一个面向 EN、RU、SEA 三类市场的 7 日新手活动。A 为基础签到奖励，B 为签到加任务引导的备选文案。上线前会确认当地语言、时区、活动规则、奖励发放、支付与客服转单口径；第 1 日检查登录/付费工单，第 7 日复盘活动参与、留存及贡献利润。若退款或奖励延迟激增，先核验事件与后台订单，再由客服与产品核对补偿流程，避免仅依据平均指标决定扩量。

## 输入、输出与复现

运行 `python3 game_ops_case.py`，无需第三方依赖。固定随机种子生成 2,400 名模拟玩家（A/B 各 1,200，EN/RU/SEA 各 800），以及 248 条模拟反馈；输出 `output/players.csv`、`output/feedback.csv`、`output/summary.json`。重新运行后会覆盖这三份文件。

## 校验后的结果与决策

| 指标 | A | B | 判断 |
| --- | ---: | ---: | --- |
| 活动参与率 | 32.58% | 38.75% | 差值 6.17 个百分点，95% 区间 2.35—9.99 个百分点 |
| D7 留存率 | 20.42% | 21.83% | 差值 1.41 个百分点，95% 区间 -1.86—4.68 个百分点；证据不足以声称留存改善 |
| 购买人数 | 50 | 73 | 模拟结果，需核验付费用户结构与退款 |

工单分为登录 60、付费 40、活动规则 50、本地化 50、奖励延迟 48；将登录及付费共 100 条设为 P1，形成示例客服升级清单。两组总收入 1,228.77 美元，假设渠道费 30%，素材/本地化/客服/买量合计 380 美元，贡献额 480.14 美元，贡献率 39.07%。该成本情景是自定假设，不代表真实游戏单位经济模型或公司利润。

**验证：**代码检查玩家 ID 唯一、分流人数、工单主题数量和利润核算。样本为虚构，因此统计区间只是展示复盘方法，不能推广到真实玩家。下一步若有真实授权数据，应先明确 D1/D7 口径、事件时间窗、随机分流、地区差异、退款与异常登录样本，然后再判断活动价值。
